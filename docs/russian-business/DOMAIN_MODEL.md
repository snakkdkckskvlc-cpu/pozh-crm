# Доменная модель: что заводить в Twenty объектами

Поля сняты из работающей базы (`infrastructure/db.py`), а не придуманы. Рядом с
каждой сущностью — то, что уже оплачено ошибками и должно переехать вместе с
полями.

---

## 1. Контрагент (organization) — 14 полей

```
наименование* · адрес · телефон
ОКПО · ОГРН · ИНН · КПП
банк · БИК · расчётный счёт · корреспондентский счёт
основная (флаг) · создана
```

**Наименование уникально без учёта регистра и с русской раскладкой.** В базе для
этого заведено своё правило сравнения (`NOCASE_UNICODE`): штатное сравнение
SQLite не считает «ООО ПОЖСЕРВИС» и «ООО ПожСервис» одним и тем же. В Twenty
надо проверить, как с этим у PostgreSQL, и **не считать вопрос решённым сам
собой**.

**Все семь реквизитов проверяются контрольными суммами на вводе, а не по кнопке
потом.** Это единственная вещь, которую в этой сущности нельзя потерять: она
ловит перестановку соседних цифр и потерянный разряд, то есть ровно то, что не
видно глазами. Расчётный счёт проверяется **вместе с БИК** по алгоритму ЦБ —
отдельно от банка его проверить нельзя.

Честное ограничение, которое надо повторить в интерфейсе: офлайн ловятся только
опечатки. Что организация существует и не ликвидирована, контрольная сумма знать
не может.

## 2. Машина (vehicle) — 25 полей

```
позывной* · госномер · марка · модель · год · категория
тип топлива · бак (мл) · пробег (м) · состояние
ГЛОНАСС (флаг) · идентификатор трекера
норма расхода (сотые доли) · форма путевого листа
гаражный номер · код машины · код топлива · организация
примечание · активна · создана
```

**Пробег в метрах, бак и топливо в миллилитрах, норма в сотых долях.** Целыми
числами, потому что топливо складывается сотнями рейсов, и погрешность дробных
чисел даёт расхождение с бухгалтерией, которое нечем объяснить.

**ГЛОНАСС стоит на трёх машинах из двенадцати.** Модуль, построенный вокруг
трекера, оставил бы девять машин без учёта. Поэтому все поля заполнимы человеком,
а источник записи помечается отдельно (`source` у рейса).

## 3. Водитель (driver) — 11 полей · **персональные данные**

```
ФИО* · табельный номер
серия и номер удостоверения · когда выдано · категории
СНИЛС · карточка водителя
активен · создан
```

**СНИЛС и номер удостоверения — обязательные реквизиты путевого листа**, хранение
согласовано с владельцем. Правила, которые обязаны переехать:

- в списковых ответах эти поля **не отдаются** — только в карточке и по праву.
  В нынешнем приложении это сделано отдельным запросом специально;
- водитель с выписанными листами **не удаляется, а помечается неактивным**:
  иначе сданный документ лишится обязательных реквизитов;
- СНИЛС проверяется контрольным числом. Номера младше 001-001-998 контрольного
  числа не имеют — это не ошибка, а исторические номера, и отвергать их нельзя.

Для Twenty это главный вопрос к правам: **нужно ограничение на уровне отдельного
поля**, а не только объекта.

## 6. Рейс (trip) — 27 полей

```
машина* · водитель · откуда · куда · адрес назначения · цель
выехал · вернулся · пробег на выезде и возврате (м)
выдано топлива (мл) · норма расхода
источник записи (ручной / трекер)
путевой лист · порядковый номер в листе
код заказчика · пользователь · грузоотправитель · …
```

**Машина в рейсе не может уехать второй раз.** Понятная ошибка вместо второй
записи: «Машина уже в рейсе — сначала отметьте возврат».

**Смежные рейсы склеиваются при подсчёте времени.** Ошибка уже была на соседней
функции: отметка посередине дробила пребывание надвое, и пятьдесят часов
показывались как двадцать пять.

## 7. Путевой лист (waybill) — **98 полей**

Столько их не по недосмотру: это государственная форма с обязательными
реквизитами, и половина полей нужна ровно затем, чтобы документ приняли.

Что обязано переехать:

- **номер уникален только среди выписанных.** В базе для этого частичный
  уникальный индекс: черновики номеров не занимают;
- **номер берётся из отдельного счётчика, который только растёт.** По максимуму
  из выписанных удалённая пачка отдала бы свои номера повторно, а повтор номера
  — недействительный документ. Это уже ловилось тестом: первая редакция считала
  именно по максимуму;
- **норма расхода топлива пишется в лист копией, а не ссылкой.** Приказ меняет
  норму, и без снимка пересчёт закрытого месяца дал бы не те цифры, по которым
  списали;
- **нет утверждённой нормы — в бланке прочерк**, а не «примерно по паспорту».
  По этой цифре списывают топливо.

## 8. Договор обслуживания (service_contract) — 11 полей
```
контрагент* · объект · номер · сумма (коп) · периодичность
предмет · действует с · действует по · активен · создан
```
Квартальные договоры закрываются только в конце квартала.
**Итог месяца считается по актам, а не по всем документам:** акт и счёт
выписываются на одну работу, и сложение удвоило бы месяц.

## 9. Огнетушитель (extinguisher) — 16 полей
```
номер* · тип · объект · место · организация
введён в · последняя проверка · последняя перезарядка
периодичность проверки и перезарядки (мес)
следующая проверка · следующая перезарядка · состояние · примечание
```

## 10. Правило срока (deadline_rule) — 8 полей
```
название* · справочник · поле · за сколько дней · что делать · включено
```
Движок сроков общий: правило смотрит на поле-дату в любом справочнике и порождает
предупреждение. Так закрываются и поверки, и перезарядки, и окончания договоров
одним механизмом.

## 11. Движение документа (doc_flow) — 12 полей
```
вид · номер · контрагент · предмет · сумма (коп)
состояние · у кого лежит · срок
кем заведён · когда заведён · когда закрыт
```

Состояния и переходы закрыты явно:
```
в работе → завизирован | отклонён | закрыт
завизирован → закрыт | отклонён
отклонён → в работе | закрыт
закрыт → (никуда)
```

**Время считается в рабочих часах:** Пн–Пт, 8:30–17:30, час обеда. Календарный
счёт делал цифры несопоставимыми с картой процессов и попросту неправдивыми:
счёт, отданный в пятницу в 17:00 и завизированный в понедельник в 9:00, по
календарю лежал 64 часа, а по факту полтора рабочих.

## Что из этого проверить в Twenty первым делом

| Нужно | Почему это риск |
|---|---|
| Тип для денег целыми копейками | Дробные числа для денег запрещены; надо знать, что предлагает Twenty |
| Своё уникальное ограничение, в том числе частичное | Номер путевого листа уникален только среди выписанных |
| Сравнение строк без учёта регистра по-русски | Штатное сравнение не считает «ПОЖСЕРВИС» и «ПожСервис» одним |
| Ограничение на уровне поля | СНИЛС нельзя отдавать в списках |
| Пометка «неактивен» вместо удаления | Сданный документ не должен терять реквизиты |
| Внешний идентификатор записи | Чтобы повторный перенос не плодил дубли |
| Снимок значения вместо ссылки | Норма расхода в закрытом документе не должна меняться задним числом |
