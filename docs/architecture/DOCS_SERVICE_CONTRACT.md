# Контракт: Twenty ↔ сервис документов

Следствие [ADR-001](adr/0001-dva-produkta-i-gde-zhivut-fajlovye-instrumenty.md).
Существующее приложение на Python остаётся сервисом документов; Twenty получает
экраны. Здесь описана граница между ними.

Граница описывается ДО первой строчки кода намеренно. Без неё Twenty начнёт
лезть внутрь сервиса, сервис — в базу Twenty, и через полгода это будет одна
система, которую нельзя развивать по частям.

---

## Что за что отвечает

| | Twenty | Сервис документов |
|---|---|---|
| Кто пользователь, кто вошёл | **да** | нет, доверяет пропуску |
| Контрагенты, машины, договоры | **да** | нет |
| Задачи, процессы, согласования | **да** | нет |
| Хранение файла | ссылка и метаданные | **сам файл, зашифрованный** |
| Разбор файла, арифметика | нет | **да** |
| Работа модели, поиск по нормативке | нет | **да** |
| Генерация DOCX и XLSX | нет | **да** |

Правило одной строкой: **Twenty знает про бизнес, сервис документов знает про
файлы. Ни один не лезет в чужую половину.**

---

## Вход: один, и он в Twenty

У сервиса документов **не остаётся своей формы входа**. Иначе два списка
сотрудников, два места, где заводят и отключают людей, и неизбежное расхождение.

```
Человек → входит в Twenty → Twenty выдаёт подписанный пропуск
        → экран зовёт сервис документов, прикладывая пропуск
        → сервис проверяет подпись и срок, дальше работает от имени этого человека
```

Требования к пропуску:
- подписан ключом, который знают обе стороны;
- содержит: кто (идентификатор сотрудника), в каком рабочем пространстве, до
  какого времени действует;
- **живёт минуты, а не часы.** Пропуск, который лежит в браузере сутки, — это
  ключ от документов компании;
- сервис документов проверяет подпись **сам**, а не спрашивает Twenty на каждый
  запрос: иначе падение Twenty останавливает и разбор файлов.

Чего в пропуске быть не должно: персональных данных, названий документов, ролей
с человеческими именами. Только идентификаторы.

---

## Файл ходит один раз

Загрузка идёт **сразу в сервис документов**. Twenty хранит только ссылку.

Причина не в скорости. Если файл ляжет и там и там, обещание «документы на диске
зашифрованы» придётся давать дважды и выполнять в двух местах — а его уже давали
заказчику, и в договоре с НЛМК есть раздел о конфиденциальности со штрафом.

```
Экран → POST /api/v1/файлы (файл + пропуск) → сервис шифрует и кладёт у себя
      ← идентификатор файла
Экран → сообщает Twenty идентификатор → Twenty связывает его с записью
```

Скачивание — только через сервис документов, с проверкой владельца.
**Чужой файл отдаёт 404, а не 403:** 403 подтверждает, что файл существует.

## Набор ручек

Версия в пути (`/api/v1/`), чтобы Twenty не ломался от изменений внутри сервиса.

| Ручка | Что делает |
|---|---|
| `GET /api/v1/здоровье` | жив ли сервис, поднята ли модель, доступен ли поиск по нормативке |
| `GET /api/v1/возможности` | список функций, которые сервис умеет **прямо сейчас** |
| `POST /api/v1/файлы` | принять файл, вернуть идентификатор |
| `GET /api/v1/файлы/{id}` | отдать файл владельцу |
| `POST /api/v1/проверки/{имя}` | запустить проверку над файлом |
| `GET /api/v1/задачи/{id}` | состояние долгой задачи |

### Почему есть «возможности»

Модель может быть не поднята, поиск по нормативке — не проиндексирован. Экран
обязан знать это **до** того, как человек выберет файл и нажмёт кнопку.

Это прямое следствие уже допущенной ошибки: в нынешнем приложении шесть рабочих
экранов показывали красное «работать нельзя», потому что была недоступна модель,
которую эти экраны не используют вовсе. Обратная ошибка — обещать работу там,
где её не будет, — стоит дороже.

Поэтому ответ «возможности» перечисляет функции и для каждой говорит: доступна,
доступна частично (и чего не будет), недоступна (и почему, словами для человека).

### Ответ проверки — всегда одной формы

```
результат:
  всё_сходится: да / нет
  проверено:    сколько строк, ячеек, документов
  находки:      [ где · что не так · должно быть · в документе · разница ]
  заметки:      [ чего сделать не удалось и почему ]
  разбор:       как программа поняла файл (какая колонка чем считается)
```

Два поля здесь неочевидны и оба обязательны.

**`заметки`** — про молчаливую деградацию. Если что-то проверить не удалось, об
этом говорят вслух: иначе человек прочитает «находок нет» как «всё хорошо». В
нынешнем приложении это худший вид отказа, и он случался трижды.

**`разбор`** — про догадку. Определение колонок по названиям — это догадка, и
отчёт, построенный по неверно понятой колонке, выглядит правильным. Показывать
разбор надо всегда, а не только при ошибке.

---

## Долгие задачи

Разбор книги Excel — секунды, анализ договора моделью — минуты.

- быстрое считается сразу и отвечает результатом;
- долгое кладётся в очередь, ручка возвращает идентификатор задачи;
- результат переживает перезапуск сервиса: человек ждал его минутами;
- очередь честная между людьми: тридцать сотрудников и одна модель, и один
  человек с пачкой договоров не должен занять её на час.

Всё это в сервисе уже есть и переносить не нужно.

---

## Когда сервис недоступен

Экран обязан сказать **«проверка документов сейчас недоступна»** и назвать, что
делать. Пустой результат, вечное ожидание и молчание запрещены.

Это новое место отказа, которого в нынешнем приложении не было: раньше всё жило
в одном процессе. Появление сети между своими службами — цена решения ADR-001, и
её надо платить осознанно.

---

## Что сервис документов НЕ делает

- не ходит в базу Twenty;
- не знает про контрагентов, сделки и задачи;
- не решает, кому что можно, — только проверяет пропуск;
- не ходит в интернет вообще (это его главное свойство, `netguard`).

Как только сервису понадобится «посмотреть в CRM» — это признак, что функция
выбрана не на той стороне границы. Правильный ход: Twenty достаёт нужное и
передаёт параметром.

---

## Чем проверим, что контракт живой

- сервис поднят, Twenty поднят, **модель намеренно погашена** → экран проверки
  реквизитов работает полностью, а экран анализа договора честно говорит, что
  недоступен;
- сервис погашен целиком → экраны говорят внятную фразу, Twenty работает;
- просроченный пропуск → 401 и понятный текст, а не пустой экран;
- чужой файл → 404;
- перезапуск сервиса во время долгой задачи → результат не потерян.
