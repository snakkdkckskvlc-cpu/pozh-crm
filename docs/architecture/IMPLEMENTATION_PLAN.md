# План реализации

Составлен по итогам Фазы 0 ([аудит](TWENTY_AUDIT.md), [опись](../migration/POZHSERVIS_INVENTORY.md),
[ADR-001](adr/0001-dva-produkta-i-gde-zhivut-fajlovye-instrumenty.md)).

Порядок — из [стратегии переезда](../migration/MIGRATION_STRATEGY.md): по одной
функции, старое приложение работает, пока новое её не перекроет.

## P0 — то, ради чего затевалось

### P0.1. Схема на бумаге — до того, как её заведут мышкой

**Почему первым.** Тип поля в Twenty **нельзя изменить после создания**:
ошиблись — только удалить вместе с данными. У нас одиннадцать сущностей и около
двухсот полей. Одна невнимательная минута при настройке стоит потерянных данных.

Выход: [DOMAIN_MODEL](../russian-business/DOMAIN_MODEL.md) дополняется точным
типом Twenty для каждого поля и проверяется целиком, прежде чем заводить первый
объект.

**Отдельно решить: как вводятся деньги.** Штатный экран Twenty теряет копейки
при вводе. Все суммы, попадающие в документы, идут через нашу форму с проверкой.

### P0.2. Выключить два обхода ограничений агента

Интерпретатор кода и логические функции позволяют агенту обойти собственные
права. Оба выключаемы, но по умолчанию про них никто не подумает. Первый день,
пять минут, и записать в настройки установки.

### P0.3. Фирменный вид

Скрипт-накладка готов и проверен. Осталось: логотип, название продукта, значок
вкладки, страница входа. Прогоняется заново при каждом обновлении Twenty.

### P0.4. Служба документов: контракт

Сделано: [пропуск](../../../fire-safety-assistant) и ручки `/api/v1/здоровье`,
`/api/v1/возможности`, `/api/v1/кто-я`.

Осталось: приём и выдача файла, запуск проверок, долгие задачи.

### P0.5. Первая функция целиком — «Проверка реквизитов»

Проверка ADR-001 на живом примере, с замером. Выбрана потому, что автономна, не
зависит от модели, результат сверяется с настоящими реквизитами компании, и
ошибка ничего не стоит.

**Если связка окажется дороже переписывания этой функции на TypeScript —
ADR-001 пересматривается, и это записывается отрицательным результатом.**

### P0.6. Справочники

Контрагенты, машины, водители, прицепы, точки. Здесь узнаём цену объектов
Twenty на практике: типы полей, уникальность, сравнение строк по-русски.

**Персональные данные водителя — отдельным объектом.** Права на поле в Twenty
есть, но разделения «в списке нет, в карточке есть» нет, а СНИЛС в списковых
ответах отдавать нельзя.

Перенос из SQLite — читающий, повторяемый, со сверкой числами и проверенным
возвратом.

### P0.7. Движение документа — первый процесс

Простейший: четыре состояния, явные переходы, время в рабочих часах.
Подтверждение человеком берём штатное — оно есть и ждёт сколько угодно.

**Не строить процесс на вкладке «Задачи» внутри карточки:** там найден наш
собственный дефект «фильтр после обрезки».

### P0.8. Движок задач — главный кастомный модуль

Подзадачи, чек-листы, зависимости, учёт времени, повторяемость. В Twenty этого
нет в коде вообще, так что объём понятен: это не доработка, а разработка.

### P0.9. Остальные файловые функции

Двенадцать штук по дорожке P0.5. Порядок — по частоте использования.

### P0.10. Первый агент

Только после того, как есть записи, задачи и процессы. Агент без них — кнопка
«спросить у нейросети», а не исполнитель.

Модель локальная через штатный механизм. Поиск по документам остаётся у нас.

## Решения, которые нужны от владельца

Ни одно не блокирует P0.1–P0.5, но чем раньше, тем дешевле.

1. **Покупать ли платную лицензию** ради правила «человек видит только свои
   записи». Это единственное платное, что нам по делу нужно. Без него
   разграничение придётся строить самим и оно будет слабее.
2. **Что говорим заказчику про офлайн.** Обработка документов остаётся в нашей
   службе и там обещание сохраняется как свойство кода. Но интерфейс теперь
   веб-приложение, и это надо проговорить прямым текстом.
3. **Список файлов целостности** в Twenty неприменим. Чем заменяем обещание
   «программа откажется работать, если её подменили».
4. **Шифрование документов** остаётся у службы документов. Файлы, которые будет
   хранить сам Twenty (вложения к записям), шифруются иначе — решить, как.

## Как поймём, что шаг сделан

Не «код написан», а:

- [ ] функция открывается из меню;
- [ ] сквозной прогон с настоящим входом зелёный;
- [ ] новые защиты доказаны поломкой;
- [ ] экран открыт глазами;
- [ ] в старом приложении функция выключена;
- [ ] записано, что осталось непроверенным.
