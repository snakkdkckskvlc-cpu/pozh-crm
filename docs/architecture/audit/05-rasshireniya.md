# 05. Расширения: можно ли добавить свой экран

**Область:** механизм приложений Twenty — что это, может ли приложение дать нам
свой экран с загрузкой файла, и что дешевле: приложение или правка форка.
**Репозиторий:** Twenty 0.2.1, коммит `b5826b2d`. Читался код; кроме того
опрашивалась работающая база и измерялась скорость разбора данных на этой машине.
**Дата:** 12.08.2026

Каждое утверждение помечено уровнем доверия:
**ПРОВЕРЕНО** — прочитан код (указаны файл и строки) или получен ответ от
работающей программы;
**СЛЕДУЕТ ИЗ КОДА** — вывод однозначен, но цепочка целиком не прослежена;
**ПРЕДПОЛОЖЕНИЕ** — не проверял.

---

## Ответ одной строкой

**Свой экран приложение добавить может** — полноценную страницу с пунктом в
левом меню, формой, кнопкой и таблицей. Это не обходной путь, а штатная
возможность, и в репозитории есть два работающих примера.

**Но именно нашу задачу этот механизм не решает.** Экран приложения выполняется
в наглухо изолированной песочнице, и оттуда **невозможно передать содержимое
выбранного файла**. Окно выбора файла открывается, имя файла приходит, а байты —
нет: этот путь закрыт в трёх местах сразу, и все три закрыты намеренно.

Для тринадцати наших файловых экранов остаётся три пути, и **рекомендуемый —
не тот, что кажется очевидным**: наш экран целиком рисует наша служба на Python,
а Twenty даёт ему рамку (страницу и пункт меню). Ни строчки правок в Twenty, ни
пересборки, ни песочницы.

## 1. Пять названий и что за ними стоит

**ПРОВЕРЕНО.** В задании перечислены пять папок. Три из них — рабочие, одна
пустая заглушка, одна — служебная библиотека. Разбираемся по порядку, потому что
без этого дальше читать бесполезно.

| Папка | Что это на самом деле |
|---|---|
| `packages/twenty-sdk` | **Главное.** Набор для написания приложений плюс программа командной строки `twenty`. Здесь и «как описать объект», и «как собрать», и «как поставить на сервер» |
| `packages/twenty-apps` | **Склад примеров.** Здесь не код Twenty, а готовые приложения: три учебных, два внутренних и четыре набора для тестов |
| `packages/twenty-cli` | **Пустышка.** Внутри один файл, который печатает «этот пакет устарел, поставьте twenty-sdk» и завершается с ошибкой |
| `packages/twenty-client-sdk` | Библиотека для обращения к данным Twenty из приложения: запросы к базе через API, три варианта (`core`, `metadata`, `rest`) |
| `packages/twenty-front-component-renderer` | **Песочница.** Тот самый механизм, который запускает чужой экран так, чтобы он не мог навредить. Именно он определяет, что нашему экрану можно, а что нельзя |

**ПРОВЕРЕНО.** `packages/twenty-cli/package.json` — описание пакета дословно
начинается со слова `[DEPRECATED]`, а `deprecate.js` печатает предложение
поставить `twenty-sdk` и выходит с кодом ошибки. **Вывод: про twenty-cli можно
забыть, это след прошлой версии.**

## 2. Что такое приложение в Twenty

### 2.1 Приложение — это папка с описаниями, а не программа

**ПРОВЕРЕНО.** Приложение — набор файлов, каждый из которых объявляет одну вещь.
Полный перечень того, что вообще бывает, задан типом «манифест» —
`packages/twenty-shared/src/application/manifestType.ts:33-52`:

| Что объявляется | Смысл по-человечески |
|---|---|
| `objects`, `fields`, `indexes` | свои таблицы, свои колонки, свои указатели для быстрого поиска |
| `logicFunctions` | логические функции — куски кода, которые выполняются на сервере |
| `frontComponents` | **экраны и части экранов** |
| `pageLayouts`, `pageLayoutTabs` | **страницы: из каких кусков собраны** |
| `navigationMenuItems` | **пункты в левом меню** |
| `commandMenuItems` | пункты в командном меню (то, что открывается по горячей клавише) |
| `views`, `viewFields` | представления: какие колонки, какой фильтр, какая сортировка |
| `roles`, `permissionFlags` | свои роли и свои права |
| `agents`, `skills` | свои ИИ-помощники и их умения |
| `connectionProviders` | подключение к чужим службам через вход по паролю провайдера |
| `publicAssets` | картинки, значки, логотип приложения |
| `translations` | переводы подписей |

**Это существенно больше, чем ожидалось.** Приложение не «дополняет мелочи», а
может привезти с собой целый рабочий раздел: свои таблицы, свои экраны, свои
пункты меню, свои права и своего помощника.

### 2.2 Где живёт

**ПРОВЕРЕНО (опросом работающей базы).** В базе развёрнутого у нас Twenty есть
все нужные таблицы:

```
core.application          core.applicationVariable
core.frontComponent       core.logicFunction
core.pageLayout           core.navigationMenuItem
core.commandMenuItem
```

То есть приложение после установки — это записи в базе плюс собранные файлы в
хранилище. **Никакой отдельной службы приложение не поднимает.**

**ПРОВЕРЕНО.** Собранный экран приложения фронтенд забирает у сервера во время
работы, по адресу вида `/rest/front-components/<id>/<контрольная сумма>.js` —
`packages/twenty-front/src/modules/front-components/utils/getFrontComponentUrl.ts:5-14`.
**Следствие, важное для нас: установка приложения НЕ требует пересборки
интерфейса Twenty.** Экран приезжает как данные.

### 2.3 Как ставится

**ПРОВЕРЕНО.** Три команды —
`packages/twenty-sdk/src/cli/commands/app/index.ts:11-53`:

| Команда | Что делает |
|---|---|
| `twenty app:publish --private` | собирает приложение в архив и кладёт **в реестр своего сервера** |
| `twenty app:install` | ставит ранее выложенное приложение на сервер |
| `twenty app:uninstall` | снимает |

**ПРОВЕРЕНО.** Без ключа `--private` публикация уходит в npm (внешний интернет) —
`packages/twenty-sdk/src/cli/commands/app/deploy.ts:28-48`. **С ключом
`--private` весь путь остаётся внутри нашего контура**: собрали архив, отправили
на свой сервер, поставили с него же (`deploy.ts:50-85`,
`packages/twenty-sdk/src/cli/operations/install.ts:20-35`). Для закрытого
контура ПожСервиса это принципиально: интернет не нужен ни разу.

**ПРОВЕРЕНО.** Сборка приложения делается esbuild — быстрым сборщиком
(`packages/twenty-sdk/src/cli/utilities/build/common/esbuild-one-shot-build.ts`).
Это не та тяжёлая сборка, которая по разделу 08 не влезает в 8 ГБ. **Приложение
собирается на машине разработчика без проблем.**

### 2.4 Ещё одна дверь, о которой стоит знать: панель настроек

**ПРОВЕРЕНО.** Кроме экранов приложение может объявить **свою страницу
настроек** — `packages/twenty-sdk/src/sdk/define/front-component/define-settings-front-component.ts`.
Туда естественно вынести адрес нашей службы документов и прочее, что не должно
быть зашито в код.

**ПРОВЕРЕНО.** Настройки приложения могут быть помечены как **тайные** —
`packages/twenty-shared/src/application/applicationVariablesType.ts:39-44`
(`isSecret: true`). Значение такой настройки не показывается обратно и приезжает
в логическую функцию через окружение. Годится для ключа доступа к нашей службе.

## 3. Свой экран: можно. Как именно

### 3.1 Короткий ответ

**ПРОВЕРЕНО.** Да. Полноэкранная страница со своим пунктом в левом меню
собирается из трёх объявлений:

1. **Экран** — `defineFrontComponent`, обычный React-компонент;
2. **Страница** — `definePageLayout` с типом `STANDALONE_PAGE` («самостоятельная
   страница»), внутри — виджет типа `FRONT_COMPONENT`, указывающий на экран;
3. **Пункт меню** — `defineNavigationMenuItem` с типом `PAGE_LAYOUT`,
   указывающий на страницу.

**ПРОВЕРЕНО (опросом работающей базы).** Все три значения существуют в базе
нашей установки, это не заготовки на будущее:

```
core."pageLayout_type_enum"        → RECORD_INDEX, RECORD_PAGE, DASHBOARD, STANDALONE_PAGE
core."navigationMenuItem_type_enum"→ VIEW, FOLDER, LINK, OBJECT, RECORD, PAGE_LAYOUT
core."pageLayoutWidget_type_enum"  → VIEW, IFRAME, FIELD, FIELDS, GRAPH, …, FRONT_COMPONENT, RECORD_TABLE, …
```

### 3.2 Живой пример из репозитория

**ПРОВЕРЕНО.** Внутреннее приложение Twenty «Партнёры» делает ровно это.

Страница —
`packages/twenty-apps/internal/twenty-partners/src/modules/partner/self-service/page-layouts/my-profile.page-layout.ts:9-33`:

```ts
export default definePageLayout({
  universalIdentifier: MY_PROFILE_PAGE_LAYOUT_ID,
  name: 'My Profile',
  type: 'STANDALONE_PAGE',
  tabs: [{
    title: 'My Profile', position: 0, icon: 'IconUser',
    layoutMode: PageLayoutTabLayoutMode.CANVAS,
    widgets: [{
      title: 'My Profile',
      type: 'FRONT_COMPONENT',
      gridPosition: { row: 0, column: 0, rowSpan: 14, columnSpan: 12 },
      configuration: {
        configurationType: 'FRONT_COMPONENT',
        frontComponentUniversalIdentifier: MY_PROFILE_FRONT_COMPONENT_ID,
      },
    }],
  }],
});
```

Пункт меню —
`.../navigation-menu-items/my-profile.navigation-menu-item.ts:10-18`: тип
`PAGE_LAYOUT`, значок, позиция, папка в меню и ссылка на страницу.

**ПРОВЕРЕНО.** Второй пример — `packages/twenty-apps/internal/real-estate`:
там самостоятельная страница используется как сводка агентства
(`src/page-layouts/agency-dashboard.page-layout.ts:42`).

**ПРОВЕРЕНО.** Сервер отдельно проверяет связку: пункт меню типа `PAGE_LAYOUT`
обязан указывать на страницу типа `STANDALONE_PAGE`, иначе установка
отклоняется —
`packages/twenty-server/src/engine/metadata-modules/flat-navigation-menu-item/validators/utils/validate-navigation-menu-item-page-layout-reference-cross-entity.util.ts:101-120`.

### 3.3 Как страница показывается

**ПРОВЕРЕНО.** Отдельный маршрут в интерфейсе, отдельная страница —
`packages/twenty-front/src/pages/page-layout/StandalonePageLayoutPage.tsx:28-60`,
подключена в
`packages/twenty-front/src/modules/app/hooks/useCreateWorkspaceAppRouter.tsx:171-177`.
Это настоящая страница приложения, а не панель и не всплывающее окно.

### 3.4 Три другие двери, кроме полноэкранной страницы

**ПРОВЕРЕНО.** Тот же самый экран можно повесить не на страницу, а:

| Куда | Чем объявляется | Когда уместно |
|---|---|---|
| **Панель сбоку** | `defineCommandMenuItem` с типом доступности `RECORD_SELECTION` | «сделать что-то с выбранными записями» |
| **Вкладка в карточке записи** | `definePageLayout` с типом `RECORD_PAGE` | «показать про эту запись то, чего Twenty не умеет» |
| **Сводка (дашборд)** | виджет на странице типа `DASHBOARD` | графики и плитки |

**ПРОВЕРЕНО (опросом работающей базы).** Сводки — обычные записи: в каждом
рабочем пространстве есть таблица `dashboard` с колонкой `pageLayoutId`. То есть
сводку человек создаёт мышкой, без программиста, и кладёт в неё виджеты.

## 4. Где живёт код экрана, и почему это меняет всё

**ПРОВЕРЕНО.** Экран приложения **не выполняется на странице Twenty**. Он
запускается так:

1. Twenty создаёт **скрытую рамку** (`iframe`) с единственным разрешением
   `allow-scripts` — то есть без доступа к нашему адресу, к нашим печенькам и к
   нашему хранилищу браузера. `packages/twenty-front-component-renderer/src/remote/sandbox/utils/createFrontComponentSandboxIframe.ts:1-16`;
2. внутри рамки поднимается **фоновый поток** (`Web Worker`) — там нет ни окна,
   ни страницы, ни привычных возможностей браузера;
3. код приложения рисует не настоящие теги, а **описания тегов**, которые
   пересылаются наружу сообщениями и уже там превращаются в настоящую разметку
   (библиотека `remote-dom`).

**По-человечески:** это как если бы наш экран сидел в отдельной комнате и
диктовал через щель в двери, что нарисовать. Он видит только то, что ему
сказали, и может только то, что разрешено списком.

### 4.1 Что из этого следует: список разрешённого

**ПРОВЕРЕНО.** Разрешённые теги перечислены поимённо —
`packages/twenty-front-component-renderer/src/constants/AllowedHtmlElements.ts`
(692 строки). Внутри есть всё, что нужно для нашей формы: `form`, `label`,
`input` (в том числе `type="file"` с `accept` и `multiple`, строки 74-96),
`textarea`, `select`, `option`, `button`, `table`, `a`, `img`, `iframe`.

**ПРОВЕРЕНО.** Ссылка (`a`) поддерживает только `href`, `target`, `rel` —
`AllowedHtmlElements.ts:36-43`. **Атрибута `download` в списке нет**: заставить
браузер скачать файл вместо открытия можно только заголовком со стороны сервера
(`Content-Disposition`).

**ПРОВЕРЕНО.** Ссылки на `data:` (файл, собранный прямо в браузере) **запрещены** —
`host/utils/hasDangerousUrlScheme.ts:3` вместе с
`host/utils/isNavigationUrlAttribute.ts:1-8` и
`host/utils/buildHostReactPropsFromRemoteProps.ts:58-59`. Обычные ссылки
`http(s)` работают.

**ПРОВЕРЕНО.** Обращаться по сети экран может **только к трём адресам**: API
Twenty, адрес логических функций и адрес, откуда загружен сам экран —
`host/utils/buildHostFetchPolicyFromFrontComponentUrls.ts:14-33`. Любой другой
адрес отвергается с ошибкой `FRONT_COMPONENT_HOST_FETCH_BLOCKED_ORIGIN` —
`host/utils/createHostFetchEnforcingPolicy.ts:22-28`.

**ПРОВЕРЕНО.** Ответ от сервера ограничен 50 МБ —
`host/constants/MaxHostFetchResponseBodyBytes.ts:1`. Для таблицы результата это
с запасом.

**ПРОВЕРЕНО.** Готовые возможности, которые Twenty даёт экрану приложения
(`packages/twenty-sdk/src/sdk/front-component/functions/`): показать сообщение
(`enqueueSnackbar`), скопировать в буфер, перейти на другую страницу
(`navigate`), открыть панель сбоку, **показать полосу выполнения**
(`updateProgress`), спросить подтверждение (`openCommandConfirmationModal`),
узнать выбранные записи и текущего человека.

**ПРОВЕРЕНО.** Сторонние библиотеки внутри песочницы работают: в наборе проверок
есть рабочие примеры на MUI и Chakra —
`packages/twenty-front-component-renderer/src/__stories__/showcase/mui-example.front-component.tsx`
и `chakra-example.front-component.tsx`.

**СЛЕДУЕТ ИЗ КОДА.** Чего в песочнице нет: `window`, `localStorage`, прямого
доступа к странице, произвольных тегов вне списка. Всё, что нужно из окружения,
подменено заглушками — папка `src/polyfills/`.

## 5. Файл выбрать можно, содержимое отдать нельзя

**Это главная находка раздела, и она отрицательная.**

**ПРОВЕРЕНО.** Окно выбора файла открывается штатно, событие «файл выбран»
доходит до кода приложения. В наборе проверок есть работающие примеры на один
файл и на несколько —
`packages/twenty-front-component-renderer/src/__stories__/html-tag/form/input/input-file-single.front-component.tsx`
и `input-file-multiple.front-component.tsx`.

**ПРОВЕРЕНО.** Но через щель в двери передаётся **только опись файла, без
содержимого** —
`packages/twenty-front-component-renderer/src/host/utils/serializeFileList.ts:31-36`:

```ts
serialized.push({
  name: fileRecord.name,          // имя
  size: fileRecord.size,          // размер
  type: fileRecord.type,          // вид (xlsx, pdf…)
  lastModified: fileRecord.lastModified,  // когда изменён
});
```

Это весь тип целиком —
`packages/twenty-front-component-renderer/src/types/SerializedFileData.ts:1-6`.
**Байтов файла нет.** Подтверждено проверкой, которая прямо на это и написана:
`__stories__/html-tag/form/input/input-file.stories.tsx:41-47` — загружают файл
с содержимым `hello world`, а ждут в ответ `{ name: 'hello.txt', type:
'text/plain' }` и ничего больше.

**ПРОВЕРЕНО.** Обойти это тремя очевидными способами нельзя, и каждый закрыт
отдельно:

| Обход | Почему не работает |
|---|---|
| Отправить форму как обычную веб-форму (браузер сам приложит файл) | Отправка формы **всегда** отменяется хозяином страницы — `host/hooks/useHtmlHostElementProps.ts:56` вместе с `host/utils/preventDefaultThenForwardToRemote.ts:7-14` |
| Прочитать файл самому и отправить запросом | В запросе наружу тело — **строка**, двоичных данных нет — `types/HostFetchInput.ts:1-6`. Да и самого файла у кода нет: пришла только опись |
| Загрузить прямо в хранилище Twenty | Загрузка идёт потоком байтов методом `PUT` — `packages/twenty-server/src/engine/core-modules/file/file-upload/controllers/file-upload.controller.ts:26-42`. Байтов у экрана нет |

**Вывод для нашей задачи.** Из тринадцати файловых функций ПожСервиса двенадцать
начинаются словами «человек кладёт файл». **Экран приложения этот первый шаг
сделать не может.** Не «неудобно», не «медленно» — не может.

**Что это НЕ отменяет.** Экран приложения прекрасно годится там, где файл не
кладут:

- реестр на оплату **из уже заведённых в CRM счетов** — данные берутся из базы,
  на выходе ссылка на скачивание;
- проверка реквизитов **введённых в карточку** — арифметика, файла нет;
- поиск дублей **среди записей CRM** — файла нет;
- показ результата разбора, который сделала наша служба, — файла нет.

## 6. Четыре пути взамен, с ценой каждого

### Путь А (рекомендуемый). Наш экран целиком наш, Twenty даёт рамку

**Суть.** Наша служба на Python отдаёт готовую веб-страницу «Сверка таблиц». В
Twenty создаётся самостоятельная страница с виджетом типа **рамка** (`IFRAME`),
в котором эта страница и показывается. В левом меню — обычный пункт.

**ПРОВЕРЕНО.** Рамка — штатный вид виджета:
`packages/twenty-front/src/modules/page-layout/widgets/iframe/components/IframeWidget.tsx:95-113`.
Разрешения рамки: `allow-scripts allow-forms allow-popups allow-same-origin`
(строка 108). **`allow-forms` и `allow-same-origin` означают, что внутри рамки
работает всё: выбор файла, отправка формы, скачивание результата.**

**ПРОВЕРЕНО.** Ограничения ровно два: адрес должен быть `http` или `https`
(строка 83) и должен проходить проверку `getSafeUrl`.

**ПРОВЕРЕНО.** Виджет-рамку можно и объявить в приложении (тип виджета
передаётся насквозь —
`packages/twenty-server/src/engine/core-modules/application/application-manifest/converters/from-page-layout-widget-manifest-to-universal-flat-page-layout-widget.util.ts:25`),
и **добавить мышкой на сводку** без всякого программиста —
`packages/twenty-front/src/modules/page-layout/hooks/useCreatePageLayoutIframeWidget.ts`,
пункт `WidgetType.IFRAME` в списке видов виджета
(`.../SidePanelPageLayoutDashboardWidgetTypeSelect.tsx:152`).

**Цена.** Тринадцать экранов пишутся один раз — на том же ванильном JS, что уже
написан в нынешнем приложении ПожСервиса (7 532 строки фронтенда по описи). В
Twenty не пишется ничего.

**Чего это стоит честно назвать:**

- **вход в систему у страницы свой.** Наша служба должна сама понимать, кто
  перед ней. Это отдельная работа: либо общий обратный прокси с одним входом,
  либо разовый ключ, который Twenty передаёт в адрес рамки;
- **вид страницы наш, а не Twenty.** Чтобы не бросалось в глаза, надо повторить
  цвета и шрифты. По разделу 08 это один файл стилей, значения уже сняты;
- **это не «единая программа», а две программы в одном окне.** Владелец должен
  понимать это прямо, а не узнать через год.

### Путь Б. Файл кладут штатным способом Twenty, дальше работает процесс

**Суть.** Человек прикрепляет файл к записи обычным способом Twenty (вложение —
это не песочница, это родной экран). Дальше срабатывает процесс: логическая
функция берёт файл и отправляет нашей службе, ответ кладёт обратно.

**Цена.** В Twenty не пишется ни одного экрана вообще. Но пользователю это
объясняется как два действия вместо одного, и **отчёт он увидит не сразу**, а
когда процесс отработает.

**ПРЕДПОЛОЖЕНИЕ.** Цепочку «логическая функция читает вложение из хранилища
Twenty» я не прослеживал до конца — знаю, что файлы отдаются по адресу с
временным ключом, но код чтения из логической функции не смотрел. **Это надо
проверить до того, как путь Б попадёт в план.**

### Путь В. Свой экран прямо в коде форка

**Суть.** Мы форкаем Twenty и не обновляемся, значит можем просто дописать
страницу в `twenty-front`: добавить маршрут в
`useCreateWorkspaceAppRouter.tsx:150-200` и свой пункт в левое меню.

**Что здесь хорошо.** Ни песочницы, ни ограничений: файл читается, отправляется,
скачивается. Полный доступ ко всем готовым частям интерфейса Twenty — таблицы,
кнопки, поля выглядят точно как везде.

**Что здесь плохо, и это решающее.**

**ПРОВЕРЕНО (раздел 08 аудита).** Полная сборка внешней части Twenty **не влезает
в 8 ГБ памяти** и должна выполняться на боевом сервере. Значит **каждая правка
экрана — это пересборка на сервере**. Не «раз в квартал», а каждый раз, когда
надо поправить подпись на кнопке.

**ПРОВЕРЕНО.** Пункт меню типа «ссылка» (`LINK`) для собственной страницы не
годится: код принудительно дописывает `https://` ко всему, что не начинается с
`http` —
`packages/twenty-front/src/modules/navigation-menu-item/display/link/utils/getLinkNavigationMenuItemComputedLink.ts:6-11`.
То есть ссылка всегда считается внешней. Свой пункт меню придётся дописывать в
код боковой панели — ещё одна правка в чужом файле.

### Путь Г. Гибрид: рамка + приложение

**Суть.** Рамка (путь А) для того, что связано с файлом. Экран приложения (§3)
для того, что связано с данными CRM. Одно приложение привозит и то и другое:
объявляет и страницу с рамкой, и страницу со своим экраном, и пункты меню, и
свои объекты, и права.

**Это и есть рекомендация.** Приложение становится «упаковкой» всего нашего
раздела: поставили одной командой — появились и таблицы, и экраны, и меню, и
права. Ставится и снимается целиком, переносится на другой сервер одной
командой.

## 7. Свои объекты, поля и действия процессов

**Коротко: да, всё три — и это самая беспроблемная часть механизма.**

### 7.1 Объекты и поля

**ПРОВЕРЕНО.** Объект объявляется одним файлом. Живой пример —
`packages/twenty-apps/examples/postcard/src/objects/post-card.object.ts:19-84`:

**ПРОВЕРЕНО.** Объявляются также связи между объектами, указатели для скорости

**ПРОВЕРЕНО.** Логическая функция объявляется шагом визуального конструктора

**ПРОВЕРЕНО.** Та же функция одновременно объявляется **инструментом для

**ПРОВЕРЕНО.** Живой пример «одна функция — три двери»:
`packages/twenty-apps/examples/document-generator/src/logic-functions/generate-document.ts:11-38`

**Это ровно та развязка, которая нужна нам:** одна проверка реквизитов, вызываемая
и из процесса, и помощником, и с экрана.

**ПРОВЕРЕНО.** Другие способы запуска логической функции —

## 8. Логические функции: где, сколько, что можно

### 8.1 Где выполняются

**ПРОВЕРЕНО.** Два двигателя на выбор —
`packages/twenty-server/src/engine/core-modules/logic-function/logic-function-drivers/logic-function-driver.factory.ts:47-100`:
`LOCAL` (на нашем сервере) и `LAMBDA` (в облаке Amazon). Плюс `DISABLED`.

**Нам подходит только `LOCAL`.** Облако Amazon в закрытом контуре не обсуждается.

**ПРОВЕРЕНО.** `LOCAL` — это **отдельный процесс Node на нашем сервере**:
`spawn(process.execPath, [runnerPath], …)` —
`.../drivers/local/services/local-child-process-runner.service.ts:154-157`. Не
песочница, не виртуальная машина. Обычная программа, запущенная нашим сервером.

### 8.2 ⚠️ По умолчанию в бою они ВЫКЛЮЧЕНЫ

**ПРОВЕРЕНО.** Значение по умолчанию —
`packages/twenty-server/src/engine/core-modules/twenty-config/config-variables.ts:698-701`:

```ts
LOGIC_FUNCTION_TYPE: LogicFunctionDriverType =
  process.env.NODE_ENV === NodeEnvironment.DEVELOPMENT
    ? LogicFunctionDriverType.LOCAL
    : LogicFunctionDriverType.DISABLED;
```

То есть **на машине разработчика включены, на боевом сервере выключены**. Если
выключены — приложение поставится, экраны появятся, а любая попытка что-то
посчитать упадёт с внятной ошибкой
(`.../drivers/disabled.driver.ts:22-27`).

**Это надо записать в порядок развёртывания сейчас, иначе обнаружится в день
запуска.** И одновременно это удобная защита: если мы решим, что чужой код на
сервере нам не нужен вовсе, — не включать, и механизм закрыт целиком.

### 8.3 Предел по времени

**ПРОВЕРЕНО.** Предел задаётся в описании функции (`timeoutSeconds`) и жёстко
ограничен самой базой данных:
`packages/twenty-server/src/engine/metadata-modules/logic-function/logic-function.entity.ts:63` —
`CHECK ("timeoutSeconds" >= 1 AND "timeoutSeconds" <= 900)`.

| | |
|---|---|
| По умолчанию | **300 секунд** (5 минут) — `.../application-manifest/converters/from-logic-function-manifest-to-universal-flat-logic-function.util.ts:29` |
| Потолок | **900 секунд** (15 минут), запрещено базой |
| Что при превышении | процесс убивается `SIGKILL`, возвращается «Timed out after N ms» — `local-child-process-runner.service.ts:205-215` |

### 8.4 Сеть, файлы, свои пакеты

**ПРОВЕРЕНО.** Функция запускается обычным процессом Node с окружением,
унаследованным от сервера (`local-child-process-runner.service.ts:151-157`).
**Значит есть всё, что есть у Node: сеть, диск, временные папки.** Никаких
ограничений в коде запуска нет.

**ПРОВЕРЕНО.** Свои пакеты — да. Приложение везёт свои `package.json` и
`yarn.lock`, сервер разворачивает их в отдельный слой и подкладывает функции при
каждом запуске:
`.../drivers/local/services/local-layer-manager.service.ts:32-71` и
`local-child-process-runner.service.ts:13-58`.

**ПРОВЕРЕНО.** Живой пример: учебное приложение «Генератор документов» тянет
`marked` и `pdf-lib` —
`packages/twenty-apps/examples/document-generator/package.json` (раздел
`dependencies`). **Для нас это значит: библиотеку разбора Excel можно привезти
своим приложением.**

### 8.5 ⚠️ Дыра: наш запрет выхода в интернет на логические функции НЕ действует

**ПРОВЕРЕНО.** Наш запрет (`packages/twenty-server/src/pozh-netguard.ts`)
устанавливается подменой функций **внутри процесса сервера** и включается первой
строчкой `main.ts` (`packages/twenty-server/src/main.ts:4-6`).

**ПРОВЕРЕНО.** Логическая функция выполняется в **другом процессе**, который
запускается напрямую (`spawn(process.execPath, [runnerPath])`) и никакого нашего
кода не загружает. Подмена в него не попадает.

**Следствие прямым текстом: любой код, привезённый приложением, обходит наш
запрет выхода наружу.** Обещание «программа физически не может ничего
отправить» на этот кусок не распространяется.

**ПРОВЕРЕНО.** Та же дыра есть у фонового обработчика: `queue-worker.ts` тоже не
загружает наш запрет (проверено — в файле нет ни импорта, ни вызова).

**Что с этим делать — три варианта, выбор за владельцем:**

1. **не включать логические функции вовсе** (`LOGIC_FUNCTION_TYPE=DISABLED`) —
   тогда весь счёт остаётся у нашей службы на Python, где запрет работает;
2. **подмешивать наш запрет в запускаемый код** — правка в
   `local-child-process-runner.service.ts`, чтобы порождённый файл первой
   строчкой ставил запрет. Работа примерно на день, включая проверку;
3. **закрыть на уровне сети** — исходящие с сервера запрещены файрволом. Самый
   надёжный, но обещание «оно не может» превращается в «сеть настроена так».

**Это надо решить до того, как в план попадёт хоть одна логическая функция.**

## 9. Влезет ли туда книга Excel на тысячи строк

тысяч строк, поднимать надо не время, а разрешённый размер запроса.**

**ПРОВЕРЕНО.** Двоичный файл до логической функции доехать может: событие несёт

`packages/twenty-shared/src/types/LogicFunctionEvent.ts:1-18`.

**ПРЕДПОЛОЖЕНИЕ.** Сколько таких разборов сервер выдержит **одновременно**, я не
мерил. Каждый — отдельный процесс Node на 400-900 МБ. Три человека, нажавшие
кнопку разом на сервере с 8 ГБ, — уже повод задуматься. **На боевом сервере со
128 ГБ (раздел 08) это не проблема, на маленьком — проблема.**

## 10. Обращение к нашей службе на Python

Ответ разный для трёх мест, и путать их нельзя.

### 10.1 Из логической функции (на сервере) — да, без ограничений

**СЛЕДУЕТ ИЗ КОДА.** Обычный процесс Node, никаких ограничений сети в коде
запуска нет. Обращение к `http://10.0.0.5:8000/сверка` работает.

**ПРОВЕРЕНО.** Наш собственный запрет выхода наружу на этот процесс не
распространяется (§8.5) — то есть даже он не помешает.

**ПРОВЕРЕНО.** Если запрет когда-нибудь распространят и на функции (вариант 2 из
§8.5), обращение внутрь предприятия всё равно останется разрешённым: частные
диапазоны `10.x`, `172.16–31.x`, `192.168.x` и свой компьютер проходят
(`packages/twenty-server/src/pozh-netguard.ts:56-73`). **Тонкость: разрешение по
IP-адресу, а не по имени.** Обращение к `docs.pozh.local` будет отвергнуто, пока
имя не внесено в `POZH_ALLOWED_HOSTS`.

**ПРОВЕРЕНО.** Адрес службы и ключ доступа хранятся не в коде, а настройками
приложения, в том числе тайными (§2.4).

### 10.2 Из экрана приложения (в браузере) — нет

**ПРОВЕРЕНО.** Только три адреса: API Twenty, адрес логических функций и адрес
самого экрана (§4.1). Обращение к нашей службе будет отвергнуто.

**Обход штатный и правильный:** экран обращается к **своей же логической
функции**, а та — к нашей службе. Один лишний прыжок, зато вход в систему
проверяется Twenty. Именно так сделано в учебном примере (§11).

### 10.3 Из рамки (путь А) — да, но это уже не Twenty

**СЛЕДУЕТ ИЗ КОДА.** Внутри рамки страница живёт своей жизнью и обращается куда
хочет — но обращается **браузер пользователя**, а не сервер. Значит адрес нашей
службы должен быть доступен с рабочих мест сотрудников, а не только с сервера.
Для сети предприятия это обычно так, но сказать это надо вслух.

## 11. Ближайший пример в репозитории: «Генератор документов»

**ПРОВЕРЕНО.** `packages/twenty-apps/examples/document-generator` — из всего, что
есть в репозитории, ближе всего к нашей задаче: человек выбирает образец,
нажимает кнопку, получает документ и ссылку на его просмотр.

### Из чего собран

| Часть | Файлов | Что там |
|---|---|---|
| Объекты | 2 | «Образец документа», «Документ» |
| Поля | 2 | связи между ними |
| Экраны | 2 | форма создания, просмотр готового документа |
| Логические функции | 3 | создание, обращение по сети, показ страницы |
| Страницы | 2 | карточка документа, карточка образца |
| Пункты меню | 2 | «Документы», «Образцы» |
| Пункт командного меню | 1 | «Создать документ» — открывает форму панелью сбоку |
| Представления | 2 | списки |
| Помощник + умение | 2 | ИИ-помощник по составлению |
| Роль | 1 | права приложения |

### Разбор по шагам

**Шаг 1. Человек выбирает.**
`src/front-components/generate-document-form.front-component.tsx` — обычный React:
`useState`, `useEffect`, выпадающий список, две кнопки. Список образцов берётся
запросом к базе Twenty (строки 156-171) через `CoreApiClient`.

**Шаг 2. Нажатие кнопки.** Строки 205-208:

```ts
const result = await new RestApiClient().post<GenerateResponse>(
  '/s/documents/generate',
  { templateId, recordId },
);
```

Это обращение **к своей же логической функции** — ровно тот приём из §10.2.

**Шаг 3. Работа на сервере.**
`src/logic-functions/generate-document-route.ts:24-35` — функция объявлена как
обращение по сети с путём `/documents/generate`, методом `POST` и, что важно,
**`isAuthRequired: true`**. Тогда в функцию приезжает `userWorkspaceId` — кто
именно нажал.

**Шаг 4. Результат и ссылка.**
`src/logic-functions/view-document.ts:16-64` — вторая функция отдаёт готовую
**страницу целиком**, со своим типом содержимого:

```ts
new Response(html, {
  status, headers: { 'Content-Type': 'text/html; charset=utf-8' },
});
```

**Вот он, ответ про «ссылку на скачивание».** Точно так же отдаётся xlsx или
файл клиент-банка: тип содержимого `application/vnd…` плюс заголовок
`Content-Disposition`, и браузер скачивает. **ПРОВЕРЕНО, что механизм есть;
ПРЕДПОЛОЖЕНИЕ, что двоичный ответ проходит без порчи** — в примере ответ
текстовый, двоичный я не проверял.

### ⚠️ Одна деталь, которую нельзя списать

**ПРОВЕРЕНО.** У показа документа стоит **`isAuthRequired: false`**
(`view-document.ts:62`). То есть **любой, кто знает адрес и номер документа,
откроет его без входа в систему**. Для учебного примера это допустимо; у нас в
документах реквизиты контрагентов и персональные данные водителей.

**Правило для нас: `isAuthRequired: false` не появляется в нашем коде без
письменного объяснения, зачем.** Это тот самый случай, когда чужой пример
списывают целиком вместе с дырой.

### Что этот пример подтверждает и что нет

**Подтверждает:** свой экран, своя форма, своя кнопка, свой результат, своя
ссылка, свои объекты, свои пункты меню, свой помощник — всё это работает и
собрано в одном приложении.

**Не подтверждает:** ни одного файла человек здесь не кладёт. Данные берутся из
базы Twenty. **Ровно та половина задачи, которая у нас главная, в примере
отсутствует — и, как показал §5, отсутствует не случайно.**

## 12. Приложение или правка форка: честное сравнение

Мы форкаем Twenty и не обновляемся — значит правка кода разрешена. Вопрос
только в цене. Сравниваю по трём меркам, как и просили.

### 12.1 Что дешевле написать

**Приложение выигрывает, и с большим отрывом — но только там, где нет файла.**

**ПРОВЕРЕНО.** Приложение собирается esbuild на машине разработчика за секунды,
ставится одной командой, не требует пересборки Twenty
(`getFrontComponentUrl.ts:5-14` — экран приезжает как данные).

**ПРОВЕРЕНО (раздел 08).** Правка `twenty-front` требует полной пересборки
внешней части, **которая в 8 ГБ не влезает** и делается на боевом сервере.

| Что делаем | Приложение | Правка форка |
|---|---|---|
| Поправить подпись на кнопке | пересобрать приложение (секунды), поставить | **пересборка фронта на сервере** |
| Добавить экран | новый файл | новый файл + правка маршрутов + правка меню |
| Добавить объект и поля | файл описания | правка ядра, миграции, генерация типов |
| Откатить неудачное | `app:uninstall` | откат кода + пересборка |

**Но:** там, где нужен файл, приложение **не может** (§5), а правка форка —
может. Сравнивать цену того, что не работает, бессмысленно.

### 12.2 Что дешевле поддерживать

**Приложение выигрывает, и здесь причина глубже, чем скорость сборки.**

**Приложение — отдельная вещь с границей.** У него своя папка, свой
`package.json`, свои проверки, своё имя. Его можно поставить, снять, перенести
на другой сервер, посмотреть версию. Когда через два года кто-то спросит «а
откуда взялся этот экран», ответ будет: «из приложения `pozh-files`, вот папка».

**Правка форка — размазанная вещь без границы.** Экран лежит в
`twenty-front/src/pages/`, маршрут — в `useCreateWorkspaceAppRouter.tsx`, пункт
меню — в боковой панели, объект — в описаниях сущностей сервера. Через два года
никто не соберёт это в одну картинку, и главное — **никто не отличит наш код от
кода Twenty**.

**Довод против приложения, который надо назвать честно.** Мы не обновляемся, но
и Twenty не обещает, что механизм приложений не изменится. **ПРОВЕРЕНО:** версия
`twenty-client-sdk` в репозитории — `2.31.0-alpha.1`. Слово `alpha` в номере
означает, что механизм ещё меняется. Мы фиксируем версию форком, но если
однажды понадобится взять из Twenty что-то новое — приложение может перестать
собираться.

**Довод против правки форка, который тоже надо назвать.** Раздел 08 уже
показал, чем кончается «правка ядра плюс пересборка»: перекраска сначала была
записана как правка исходников, а оказалась одним файлом стилей. **Привычка
править ядро — это привычка не искать штатный путь.**

### 12.3 Что понятнее следующему человеку

**Здесь выигрывает путь А (рамка), а не приложение и не правка форка.**

Три объяснения одного и того же экрана:

| Путь | Как это звучит |
|---|---|
| **Рамка** | «Сверка таблиц — это наша программа на Python. Twenty показывает её в окошке. Код — в репозитории службы документов» |
| **Приложение** | «Сверка — экран приложения `pozh-files`. Он выполняется в песочнице, оттуда ходит в логическую функцию, та — в нашу службу» |
| **Правка форка** | «Сверка — страница в `twenty-front/src/pages/pozh/`. Маршрут — там-то, пункт меню — там-то. Чтобы поменять, надо пересобрать фронт на боевом сервере» |

**Первое объяснение понимает человек, который не программист.** Два других —
нет.

И это, пожалуй, главный довод: у ПожСервиса тридцать сотрудников и один
подрядчик на разработке. Система, которую нельзя объяснить владельцу за одну
минуту, — это система, за которую владелец не может отвечать.

### 12.4 Рекомендация

**Строим по пути Г (гибрид), с уклоном в путь А:**

1. **Тринадцать файловых экранов** — наша служба на Python, показываются рамкой.
   В Twenty не пишется ни одного экрана. Работа переносится, а не переписывается;
2. **Приложение `pozh`** — упаковка: объекты, поля, представления, пункты меню,
   страницы с рамками, роли, шаги процессов. Ставится и снимается целиком;
3. **Логические функции — только там, где нельзя иначе,** и до этого решается
   вопрос §8.5 (запрет выхода наружу на них не действует). По умолчанию —
   выключены;
4. **Правка форка — только там, где штатного пути нет вовсе,** и каждая правка
   объясняется в документе. Пока таких мест по этому разделу **не найдено ни
   одного**.

**Что надо решить владельцу до начала работы:**

- **вход в систему для страниц в рамке.** Отдельный вход или общий — это
  развилка, и она стоит денег в обе стороны;
- **логические функции: включаем или нет.** Если да — как закрываем §8.5.

## 13. Что осталось непроверенным

Честный список, чтобы никто не принял это за полный ответ.

1. **Может ли логическая функция прочитать вложение из хранилища Twenty.** От
   этого зависит путь Б. Знаю, что файлы отдаются по адресу с временным ключом;
   кода чтения из функции не смотрел.
2. **Проходит ли двоичный ответ через логическую функцию без порчи.** Нужно для
   выдачи xlsx и файла клиент-банка. В примере ответ текстовый.
3. **Насколько живой остаётся таблица результата в песочнице при тысячах
   строк.** Каждый элемент разметки пересылается через границу потока
   сообщением; на пяти тысячах строк это может подвесить браузер. **Не измерял —
   для этого нужен браузер, а не Node.** Если пойдём путём приложения для
   показа результатов, это надо измерить до, а не после.
4. **Как страница в рамке узнаёт, кто перед ней.** Разовый ключ в адресе, общий
   обратный прокси, что-то третье — не прорабатывал.
5. **Сколько одновременных разборов выдержит сервер.** Каждый — отдельный
   процесс на 400-900 МБ.
6. **Правила уровня строки и приложения.** Как ведут себя права приложения
   вместе с платным правилом «человек видит только свои записи» (раздел 06) — не
   смотрел.
