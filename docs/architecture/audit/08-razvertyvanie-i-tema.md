## 1.2. Из чего состоит связка `packages/twenty-docker`

**ПРОВЕРЕНО**, файл `packages/twenty-docker/docker-compose.yml` целиком.

Четыре службы, которые поднимаются вместе:

| Служба | Что делает | Чем важна нам |
|---|---|---|
| `server` | Сама программа: отдаёт страницы и принимает запросы, порт 3000 | Главная. При старте сама накатывает изменения базы |
| `worker` | Тот же образ, но запущен командой `yarn worker:prod` — выполняет фоновые задачи (рассылки, расписания, длинные операции) | **Отдельный процесс.** Без него не работают «Сроки» и закрытие месяца — это две наши функции |
| `db` | PostgreSQL 16, данные в отдельном хранилище `db-data` | Здесь вся CRM |
| `redis` | Кэш и очередь, запускается с `--maxmemory-policy noeviction` | Ключевая деталь: `noeviction` значит «не выбрасывай данные при нехватке памяти». С настройками по умолчанию Redis начал бы молча терять задачи из очереди |

Важные подробности, которые видно только в файле:

- **Сервер и работник делят одну папку с файлами.** Оба монтируют
  `server-local-data:/app/packages/twenty-server/.local-storage`
  (`docker-compose.yml:8-9` и `:63-64`). Если ставить без Docker — обе службы
  обязаны видеть одну и ту же папку на диске, иначе загруженный документ
  «пропадёт» при обработке.
- **Изменения базы накатывает только сервер.** У работника принудительно
  `DISABLE_DB_MIGRATIONS: "true"` и `DISABLE_CRON_JOBS_REGISTRATION: "true"`
  (`docker-compose.yml:69-70`) с комментарием «это уже делает сервер».
  Порядок запуска обязателен: сначала сервер, потом работник.
- **Что происходит при первом старте.** **ПРОВЕРЕНО**,
  `packages/twenty-docker/twenty/entrypoint.sh`: проверяется, есть ли в базе
  схема `core`; если базы нет — `yarn database:init:prod`; затем всегда
  `yarn command:prod upgrade` и регистрация задач по расписанию
  (`cron:register:all`). То есть обновление накатывается само при перезапуске.
- Рядом лежат ещё три варианта установки — Kubernetes (`k8s/`), Helm (`helm/`)
  и Podman (`podman/`). **ПРОВЕРЕНО**, `podman/README.md:3-5`: «k8s и podman
  поддерживаются сообществом, а не основной командой; команда Twenty
  поддерживает только Docker». Нам они не нужны, но знать полезно: официально
  поддержан ровно один способ.
- Есть образ «всё в одном» (`twenty-app-dev`) с PostgreSQL и Redis внутри
  одного контейнера. **ПРОВЕРЕНО**, `Dockerfile`: в нём зашит
  `APP_SECRET=twenty-app-dev-secret-not-for-production` и
  `DISABLE_DB_MIGRATIONS=true`. **В работу его брать нельзя** — это среда для
  разработчиков.

## 1.4. Память и место. Влезет ли сборка в 8 ГБ

### Короткий ответ: серверная часть — да, внешняя часть — нет

**Внешняя часть (то, что показывается в браузере) требует потолок памяти 8 ГБ
на один процесс.** **ПРОВЕРЕНО**, два независимых места:

- `packages/twenty-front/package.json:6`:
  `"build": "NODE_ENV=production NODE_OPTIONS=--max-old-space-size=8192 npx vite build"`
- `packages/twenty-docker/twenty/Dockerfile:78`:
  `NODE_OPTIONS="--max-old-space-size=8192" npx nx build twenty-front`

На машине с 8 ГБ оперативной памяти процессу, которому разрешено занять 8 ГБ,
не хватит места: часть памяти уже занята системой. Машина уйдёт в подкачку
(начнёт использовать диск вместо памяти) и либо будет собирать часами, либо
упадёт. **Так и планировалось разработчиками**: прямо над этой строкой в
Dockerfile стоит комментарий —

> To skip the memory-intensive frontend build, pre-build on the host:
> `npx nx build twenty-front`. The check below will use
> `packages/twenty-front/build/` if it already exists.

То есть в Twenty **штатно предусмотрено собрать внешнюю часть на другой машине
и подложить готовый результат**. Это ровно наш случай.

**Серверная часть на 8 ГБ собирается — это уже проверено делом.**
**ПРОВЕРЕНО**: в репозитории лежит `packages/twenty-server/dist/main.js`,
датированный сегодняшним днём, 18:37, при том что репозиторий склонирован в
18:16. Значит сборка сервера на этой самой машине прошла. Размер результата —
113 МБ.

Для сравнения, другие сборки в проекте просят ещё больше: витрина компонентов
Storybook — 10 ГБ (`nx.json:152`), запуск сервера в режиме разработки — 12 ГБ
(`.vscode/launch.json:78`). Их нам делать не нужно.

## 1.5. Можно ли поставить без Docker

**Да, но это перестаёт быть «одним скриптом», и на Windows появляется отдельная
сложность.**

### Что именно надо запустить

**СЛЕДУЕТ ИЗ КОДА** (`packages/twenty-server/package.json`, раздел `scripts` —
**ПРОВЕРЕНО**; сам порядок команд собран из `entrypoint.sh`):

```
# один раз, на пустой базе
node dist/database/scripts/setup-db.js
node dist/command/command run-instance-commands   # это database:migrate:prod

# при каждом обновлении
node dist/command/command upgrade
node dist/command/command cron:register:all

# постоянно работают две службы
node dist/main                       # сервер, порт 3000
node dist/queue-worker/queue-worker  # фоновые задачи
```

**ПРОВЕРЕНО**: все четыре точки входа есть в собранном виде —
`dist/main.js`, `dist/command/command.js`, `dist/queue-worker/queue-worker.js`,
`dist/database/scripts/setup-db.js`. Это обычные программы на Node, никаких
Linux-only вызовов в них не нужно: файлы `entrypoint.sh` и `upgrade-background.sh`
— принадлежность контейнера, а не программы.

Готовые страницы кладутся в папку `dist/front` рядом с сервером — тогда сервер
их раздаёт сам. **ПРОВЕРЕНО**, `packages/twenty-server/src/app.module.ts:96,108-114`:
если папка `front` существует, включается раздача статических файлов из неё.

### Чего это стоит на Windows

1. **PostgreSQL** ставится на Windows штатно, расширения `uuid-ossp` и
   `unaccent` входят в стандартную поставку. **ПРЕДПОЛОЖЕНИЕ** — на Windows не
   проверял, но оба расширения стандартные.
2. **Redis официальной сборки под Windows не имеет.** **ПРЕДПОЛОЖЕНИЕ.** Варианты:
   Memurai (платный совместимый сервис), Redis внутри WSL (подсистема Linux
   внутри Windows), или отдельная маленькая Linux-машина. **Важно:** чем бы ни
   заменили, надо выставить `maxmemory-policy noeviction`, иначе при нехватке
   памяти очередь начнёт молча терять задачи (в docker-compose это прописано
   явно — **ПРОВЕРЕНО**, `docker-compose.yml:129`).
3. **Официальная документация для Windows предлагает WSL.** **ПРОВЕРЕНО**,
   `packages/twenty-docs/developers/contribute/capabilities/local-setup.mdx` —
   вкладка Windows начинается с `wsl --install`. То есть даже разработку под
   Windows Twenty ведёт через встроенный Linux.
4. Две службы (сервер и работник) надо оформить как службы Windows, чтобы они
   поднимались после перезагрузки. Средствами Twenty это не решается.

### Что я бы предложил владельцу

Три варианта, честно с ценой:

| Вариант | Что даёт | Чем платим |
|---|---|---|
| **A. Docker на боевом сервере** | Официально поддержанный путь. Обновление — сменить одну строчку и перезапустить | Ставим Docker Desktop / Docker Engine на Windows-сервер. Docker в проекте до сих пор был под запретом (см. `CLAUDE.md` старого приложения) — это решение владельца |
| **B. WSL на боевом сервере** | Docker не нужен, но Linux-часть всё равно появляется — под Redis | Тот же по сути «второй мир» внутри Windows, только собранный руками |
| **C. Всё родное для Windows** | Никаких контейнеров | Redis — сторонняя платная или полусамодельная замена; две службы Windows настраиваем руками; путь нигде не описан, все грабли наши |

**ПРЕДПОЛОЖЕНИЕ**, но твёрдое: вариант A дешевле по труду и надёжнее, вариант
C дороже всего и хуже всех переживает обновления.

## 2.4. Насколько это переживёт обновление Twenty

| Способ | Переживает ли |
|---|---|
| Логотип и название через настройки | **Полностью.** Лежат в базе, обновления их не трогают |
| Файл `pozh-brand.css` + строчка в `index.html` + подменённый PNG | **Переживает, но не сам.** При обновлении папка `dist/front` заменяется целиком, три действия надо повторить. Это 6 строк в скрипте установки |
| Правки в исходниках (шаг 3 и 4) | **Плохо.** Конфликт при каждом `git pull`, разбирать руками |

Отдельный риск для файла стилей — **ПРЕДПОЛОЖЕНИЕ**: имена вроде
`--t-color-blue` появились недавно (в самом файле стоит пометка «поддерживается
в соответствии тестом»), и в будущих версиях их могут переименовать. Тогда
покраска перестанет действовать — но **тихо**, интерфейс просто вернётся к
синему. Проверить это заранее нельзя: репозиторий склонирован без истории
(**ПРОВЕРЕНО**: `git log` показывает один коммит), churn имён посмотреть не на
чем.

**Отсюда практическое требование:** после каждого обновления кто-то должен
открыть страницу входа и убедиться, что она красная. Иначе однажды люди придут
на работу в синюю программу и решат, что им подсунули не ту.

## Что это значит для переноса

1. **Красный цвет и логотип — задача одного дня, а не проекта.** Логотип и
   название — настройка. Цвет — один файл стилей, подкладываемый при установке.
   Ни строчки исходников Twenty. Это лучший расклад, на который можно было
   рассчитывать: фирменный вид перестаёт быть аргументом против Twenty.

2. **Наши будущие экраны для файловых инструментов покраснеют сами.** Экраны
   группы A (сверка таблиц, проверка счёта, реквизиты) по решению ADR-001
   живут как приложения-экраны внутри Twenty. **ПРОВЕРЕНО**,
   `packages/twenty-front-component-renderer/src/host/components/FrontComponentRenderer.tsx:84,123`
   — они рисуются тем же поставщиком темы, без отдельной обёртки, значит
   наследуют те же цвета. Отдельно красить их не придётся.

3. **Обещание «приложение не ходит в интернет» превращается в список настроек.**
   Три переключателя (`TELEMETRY_ENABLED`, `ALLOW_REQUESTS_TO_TWENTY_ICONS`,
   логотип рабочего пространства) плюс закрытая сеть. Это не то же самое, что
   `netguard`, который физически не пускает. Разницу надо проговорить с НЛМК
   до, а не после.

4. **Redis — новая обязательная служба, и её нельзя выкинуть.** Это прямо
   противоречит строке «Redis, BullMQ, Celery — не заводить» из правил старого
   приложения. Решение владельца требуется до начала работ, потому что от него
   зависит, ставим ли мы Docker/WSL на боевой сервер.

5. **Сборку внешней части делаем только на боевом сервере.** Разработчику на
   8 ГБ она недоступна. Практически это значит: разработчик правит и проверяет
   код, а собранные страницы делает сервер (или разработчик один раз получает
   доступ к серверу для сборки). Планировать сборку «у себя перед выездом» —
   значит потерять день.

6. **Работник (фоновые задачи) — не деталь, а половина функциональности.**
   Без него не работают «Сроки» (напоминания о поверке огнетушителей и
   договорах) и закрытие месяца — две функции из описи, ради которых Twenty
   и берётся. Установка обязана поднимать два процесса, а не один.

## Риски

1. **Два красных: «Сохранить» и «Удалить» станут почти одинаковыми.**
   **ПРОВЕРЕНО**, `packages/twenty-ui/src/input/Button/Button.module.scss:123-133`
   и `:136-145`: главная кнопка красится в `--t-color-blue`, кнопка удаления —
   в `--t-color-red` (`#D45452`, мягкий красный). Если сделать главную кнопку
   фирменным `#E31E24`, бухгалтер увидит две красные кнопки рядом.
   *Чем грозит:* нажатием «Удалить» вместо «Сохранить» на карточке договора.
   *Что смягчает:* удаление подтверждается отдельным окном
   (**ПРОВЕРЕНО**, `modules/ui/layout/modal/components/ConfirmationModal.tsx`).
   *Что предлагаю:* сделать шаг 2 в два приёма — сначала только блок «Акцент»
   (подсветка, рамки, значки), показать людям, и лишь потом решать, красить ли
   главную кнопку. Если красим — кнопку удаления надо увести в заметно более
   тёмный тон, а не оставлять как есть.

2. **Покраска отвалится молча при обновлении.** Если Twenty переименует
   значения `--t-*`, наш файл перестанет действовать, и никакой ошибки не
   будет — просто вернётся синий. *Чем грозит:* люди решат, что открыли не ту
   программу, или что «всё слетело». *Лечится:* обязательная проверка глазами
   после обновления и запись в чек-лист установки.

3. **Забудут перенести файл стилей при обновлении.** Папка с готовыми
   страницами заменяется целиком. *Чем грозит:* тем же самым — синий интерфейс
   на следующее утро. *Лечится:* три действия должны быть внутри скрипта
   обновления, а не в чьей-то памяти.

4. **Уже сделанная правка в `MainColorsLight.ts` и `AccentLight.ts` создаст
   ложную уверенность.** Она не красит ничего, но выглядит как сделанная
   работа, и при следующем обновлении даст конфликт. *Лечится:* откатить до
   того, как кто-то начнёт на неё опираться.

5. **Redis на Windows.** Официальной сборки нет. *Чем грозит:* если поставить
   первый попавшийся вариант с настройками по умолчанию, при нехватке памяти
   он начнёт выбрасывать данные — а там очередь фоновых задач. Секретарь
   отправит документ на обработку, задача исчезнет, ошибки не будет.
   *Лечится:* явно выставить `maxmemory-policy noeviction` и проверить это
   отдельным шагом при установке.

6. **Сборка внешней части на 8 ГБ.** Если кто-то всё-таки её запустит, машина
   уйдёт в подкачку на часы или упадёт посреди работы. *Чем грозит:* потерянный
   день разработчика и, если это делалось «по-быстрому перед установкой», —
   сорванная установка.

7. **Телеметрия включена по умолчанию.** **ПРОВЕРЕНО**,
   `config-variables.ts:882`. Если забыть выключить и контур окажется не
   полностью закрыт, программа отправит наружу событие о регистрации
   пользователя. *Чем грозит:* формально это нарушение раздела о
   конфиденциальности в договоре с НЛМК. *Лечится:* строка в `.env` плюс
   проверка на сетевом оборудовании.

8. **Значок вкладки меняется — а люди находят вкладку по нему.** В правилах
   старого приложения это прямо записано как «не трогать». Здесь мы меняем
   значок сознательно и один раз, при переходе. *Что предлагаю:* менять его
   вместе с переходом на новую программу, а не отдельным «улучшением» позже.

## Открытые вопросы

1. **Насколько часто Twenty переименовывает значения `--t-*`?** Ответа в коде
   нет: репозиторий склонирован одним коммитом, история недоступна. Нужно
   посмотреть историю файла `theme-light.css` на полном клоне за 3-4 выпуска —
   это определит, надёжен ли способ с файлом стилей или его надо страховать.

2. **Собирается ли внешняя часть на 8 ГБ на самом деле, или это только
   заявленный потолок?** Значение `--max-old-space-size=8192` — это разрешённый
   максимум, а не измеренное потребление. Реальный пик я не мерил (задание —
   только чтение). Возможно, хватило бы и 6 ГБ. Проверяется одним запуском на
   сервере с замером.

3. **Какую замену Redis выбрать под Windows и сколько она стоит?** Memurai
   платная; WSL тянет за собой Linux; отдельная машина — отдельные расходы.
   В коде Twenty ответа нет, это вопрос закупки.

4. **Приемлемо ли для НЛМК обещание «сеть настроена так, что не может» вместо
   «программа не может»?** Код на этот вопрос не отвечает. Это разговор с
   заказчиком, и он должен состояться до, а не после установки.

5. **Понадобятся ли письма (приглашения, сброс пароля) вообще?** Если люди
   заводятся администратором вручную и пароль выдаётся лично, весь блок
   переделки писем (`packages/twenty-emails`) отпадает, и шаг 3 становится
   заметно дешевле. Не проверял, обязательна ли отправка письма при создании
   пользователя.

6. **Какой размер базы будет через год?** Оценки места (60 ГБ) сделаны на
   глаз. Точнее скажет пробная загрузка данных из нынешнего SQLite.
