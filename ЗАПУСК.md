# Как поднять и посмотреть

## Быстро

```bash
cd /Users/artemharitonov/pozh-crm/twenty
export PATH="/opt/homebrew/opt/node@24/bin:$PATH"

redis-server --daemonize yes --port 6379     # если ещё не запущен
npx nx start twenty-server                    # окно 1, порт 3000
npx nx start twenty-front                     # окно 2, порт 3001
```

Открыть: **http://localhost:3001**

Демонстрационный вход: `tim@apple.dev` (пространство Apple) или
`phil@apple.dev`. Пароль подставляется сам — в настройках стоит
`SIGN_IN_PREFILLED=true`.

## Фирменные цвета

```bash
cd /Users/artemharitonov/pozh-crm
node branding/apply-branding.mjs             # поставить
node branding/apply-branding.mjs --проверить # показать, что сделает
node branding/apply-branding.mjs --снять     # убрать
```

**Пересобирать ничего не нужно** — Twenty читает цвета из переменных стилей во
время работы. Обновите страницу в браузере.

Проверить, что подействовало (консоль браузера):

```js
getComputedStyle(document.documentElement).getPropertyValue('--t-color-blue')
```

Должно вернуть `#e31e24`, а не синий.

### Когда накладку надо ставить заново

Накладка — это не настройка внутри программы, а два изменения в файлах папки
`twenty/`: файл стилей кладётся в `packages/twenty-front/public/`, а ссылка на
него дописывается в `index.html`. Перезаписали эти два места — накладки больше
нет, надо прогнать команду снова.

Раньше здесь стояла оговорка «после `git pull` в Twenty», и она устарела дважды.
Во-первых, обновления от авторов Twenty мы не берём вовсе — решение владельца,
файл `docs/architecture/adr/0002-fork-bez-obnovlenij.md`. Во-вторых, с
13.08.2026 у папки `twenty/` нет своего склада кода: она лежит внутри склада
`pozh-crm`, и забирать правки надо из корня проекта, а не изнутри `twenty/`:

```bash
cd ~/pozh-crm && git pull        # забрать свежие правки из своего склада
```

Поводов поставить накладку заново теперь ровно два:

- забрали свежие правки из своего склада, и среди них были правки `index.html`
  или содержимого `packages/twenty-front/public/`;
- развернули проект заново — на другом компьютере или на боевом сервере.

## Русский язык интерфейса

Часть перевода лежит в файлах и приезжает сама через git (словари,
исправленные места в коде Twenty). Другая часть — **записи в базе данных
этого пространства**: названия объектов («Сделки» вместо «Opportunities»),
названия видов списка, папка меню, подписи команд («Новая запись» вместо
«New»). Свежая база — хоть на новом компьютере, хоть на боевом сервере после
восстановления — этих записей не содержит вовсе, и без следующего шага
интерфейс снова станет наполовину английским.

```bash
cd /Users/artemharitonov/pozh-crm
export PATH="/opt/homebrew/opt/node@24/bin:$PATH"

# Токен — из браузера после входа администратором:
# localStorage.getItem('tokenPairState') → accessOrWorkspaceAgnosticToken.token
# На боевом сервере лучше постоянный ключ: Настройки → API keys.

TWENTY_API_TOKEN=... node branding/provision-ru-locale.mjs             # поставить
TWENTY_API_TOKEN=... node branding/provision-ru-locale.mjs --проверить # показать, что сделает
```

Прогонять безопасно повторно: скрипт сначала смотрит, что уже верно, и трогает
только расхождение. Каждая запись находится по имени, а не по номеру — на
боевом сервере, где база поднята заново, номера будут другими, а имена те же.

**Если правки не видны сразу** — сервер держит часть этих записей в памяти.
Обновление приходит через минуту-другую само; ускорить можно, перезапустив
`twenty-server` после прогона скрипта.

**Чего этот скрипт не чинит, и почему** — у своих объектов (Контрагенты,
Огнетушители…) четыре графы «Кто создал», «Когда создал», «Кто изменил»,
«Когда изменил» остаются английскими. Сервер Twenty намеренно отказывается
менять подпись у этих граф с явной ошибкой защиты — это решение разработчиков
Twenty, а не наша недоделка, и обходить его правкой базы напрямую мы не стали.

## Если что-то не поднимается

| Признак | Причина |
|---|---|
| Ошибка про версию node | не выставлен PATH на node@24 |
| Сервер не стартует, жалуется на подключение | не запущен redis или postgres |
| Порт занят | `pkill -f "nx start"` и заново |
| Интерфейс белый | подождать: первая сборка страницы занимает время |
| Цвета не поменялись | не прогнана накладка, либо не обновлена страница |

Логи прошлого запуска: `/tmp/twenty-server.log`, `/tmp/twenty-front.log`,
`/tmp/twenty-db2.log`.

## Ограничение по железу

Памяти на машине **8 ГБ**. Сборка `twenty-ui` в неё укладывается, полная сборка
фронта не пробовалась. Если что-то падает с нехваткой памяти — уменьшать
`--max-old-space-size`, а не увеличивать: своп сделает только хуже.

## Как сохранить работу

С 13.08.2026 папка `twenty/` — часть склада кода `pozh-crm`, своего отдельного
склада у неё больше нет. Раньше сохранять и отправлять приходилось дважды: одну
команду в корне проекта, вторую — внутри `twenty/`. Теперь это одна команда, и
выполняется она **из корня `~/pozh-crm`**.

Сама команда самопроверки и разбор того, что она печатает, — в
[ONBOARDING.md](ONBOARDING.md), раздел 5 «Как сохранять работу». Здесь её
намеренно нет: в двух местах команды рано или поздно разойдутся.

У службы документов (`~/fire-safety-assistant`) склад кода свой, отдельный, и
сохраняется она отдельно, в своей папке.
