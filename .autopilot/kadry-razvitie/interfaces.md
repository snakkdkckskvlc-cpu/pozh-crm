# Границы и правила — читать до первой строки кода

Этот файл читает каждый исполнитель перед работой. Он единственное, что стоит
между свежим контекстом и изобретением собственной версии каждой границы.

## Где работаем

**Склад кода: `~/fire-safety-assistant`** (служба документов), не `~/pozh-crm`.
Это правка существующего инструмента, что правило владельца «всё новое — в
Twenty» прямо разрешает делать здесь (`CLAUDE.md` §0, строка «правка
существующего файлового инструмента»).

Ветка: `main`. Перед работой `git fetch` — второй разработчик пушит туда же.

## Стек — фактический

| Слой | Что |
|---|---|
| Сервер | Python 3.13 локально, FastAPI, `./venv/bin/python` |
| База | **SQLite, штатная либа, без ORM** |
| Фронтенд | **ванильные HTML/CSS/JS, сборки нет**, `apps/desktop/frontend/views/` |
| Язык всего | русский: код, комментарии, имена таблиц и полей, тексты ошибок, коммиты |

**Новых зависимостей не ставить.** Нужна библиотека — таск возвращается как
`BLOCKED` с объяснением, установка не делается.

## Команды

```bash
./venv/bin/python -m ruff check . && ./venv/bin/python -m ruff format .
./venv/bin/python -m pytest apps/backend/tests/unit/test_<модуль>.py -q
PYTHONPATH="apps/backend/src:packages/rag/src:apps/desktop/src" \
  ./venv/bin/python -m mypy --python-version 3.13 apps/backend/src
./venv/bin/python scripts/build_integrity_manifest.py
```

**Полный `pytest` не гонять** — прямое указание владельца, ноутбук не тянет.
Только тесты своего модуля плюс сквозной прогон через `TestClient`.

## Три правила, за нарушение которых уже платили

1. **Опись целостности.** Тронул файл из описи — пересобери `integrity.json`
   **в том же коммите**, иначе программа у пользователя откажется запускаться.
   Файл порождаемый: при столкновении версий его не сливают, а пересобирают
   заново.
2. **Роутер закрывается целиком** — новый добавляется в защищённый список в
   `main.py::create_app`, а не обвешивается проверками по одной ручке.
   Регистрацию всех трёх новых роутеров делает таск 01, остальным её не трогать.
3. **Никаких не-кириллических и невидимых символов** в русских словах. Ловится
   хуком, но знать надо.

## Границы, решённые в спецификации

Копия раздела §13 спецификации. Додумывать здесь нечего.

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `services/kadry_sostav.py` | таблица `hr_состав`, вся правда о том, кто в какой группе и когда | `состав_на(conn, компания, день) -> list[Группа]`<br>`перевести(conn, кто, куда, с_дня, по_день\|None) -> Перевод`<br>`отменить(conn, id_перевода)`<br>`история(conn, кто) -> list[Период]`<br>`группы_на(conn, компания, день) -> list[str]` | склейку периодов, `вернуть_в`, возврат по окончании срока |
| `services/kadry_analitika.py` | сборка двух экранов | `как_идут_дела(conn, компании, год, месяц) -> Сводка`<br>`что_проверить(conn, компании, год, месяц) -> list[ВидПроблемы]` | пороги, запросы, группировку по трём уровням |
| `services/kadry_otsutstviya.py` | отчёт по отсутствиям | `собрать(conn, компании, с, по, охват) -> ОтчётОтсутствий` | расшифровку пометок, счёт «когда вернётся» |

| `services/kadry.py` | сотрудники, дни, отсутствия | `+ поставить_отсутствие(..., по_дату, откуда)`<br>`+ отметка_выгрузки(...)`<br>`+ месяц_выгружали(...)` | — |
| `views/kadry_brigady.py` | ручки доски бригад | `/api/кадры/состав`, `/api/кадры/перевод` | — |
| `views/kadry_analitika.py` | ручки двух экранов аналитики | `/api/кадры/как-дела`, `/api/кадры/что-проверить` | — |
| `views/kadry_otsutstviya.py` | ручки отсутствий | `/api/кадры/отсутствия`, `/api/кадры/отсутствия.xlsx` | — |

**`kadry_sostav` — единственный, кто читает и пишет `hr_состав`.** Все остальные
спрашивают у него. Прямой SQL по этой таблице из других модулей — ошибка ревью.

Существующий `views/kadry.py` остаётся как есть; новые ручки в него **не
дописываются** — иначе три таска волны 2 подерутся за один файл.

## Шов для проверок — один

**Функции служб** (`services/*`). Так уже устроены все шесть существующих наборов

## Из таска 01 — фундамент состава бригад

- `services/kadry_sostav.py` — **единственный**, кто читает и пишет `hr_состав`.
  `состав_на(conn, компания, день) -> list[Группа]` · `группы_на(...) -> list[str]`
  `история(conn, кто) -> list[Период]` · `перевести(conn, кто, куда, с_дня, по_день=None) -> Перевод`
  `отменить(conn, id_перевода) -> bool` · `перенести_старые_бригады(conn) -> int`
  `записать_месяц(conn, кто, год, месяц, куда) -> bool`
  **`расхождения_месяца(conn, компания, год, месяц) -> list[Расхождение]`** — этим
  таск 04 достаёт список несоответствий для экрана загрузки: у каждого
  `сотрудник_id`, `фио`, `руками`, `табель`, `с_даты`, `по_дату`. Загрузка табеля
  ручные переводы НЕ затирает — по умолчанию остаётся ручное, решает человек.
  `переименовать(conn, компания, было_*, стало_*, только_месяц=None) -> int` —
  зовётся из `kadry.переименовать_бригаду`, отдельно дёргать не нужно.
  Классы: `Куда`, `Человек`, `Группа`, `Период`, `Перевод`, `Расхождение`;
  виды `ВИД_БРИГАДА` / `ВИД_ОФИС` / `ВИД_УШЁЛ`;
  источники `ИСТОЧНИК_ТАБЕЛЬ` / `ИСТОЧНИК_РУКАМИ`.
  **`отменить` снимает только поставленное руками** (`источник = 'руками'`): на
  запись из табеля отвечает `False`, экрану надо это показать словами.
- Схема: `hr_состав` (+2 индекса, +графа `было_по`), `hr_выгрузка` (+индекс),
  у `hr_отсутствие` появились `по_дату` и `откуда`.
  **`hr_бригада` переименована в `hr_бригада_do_perekhoda`** — прямые запросы к
  старому имени падают.
- **Три пустых роутера уже зарегистрированы** в `main.py` и в защищённом списке:
  `views/kadry_brigady.py` (`/api/кадры/состав`), `views/kadry_analitika.py`
  (`/api/кадры/как-дела`), `views/kadry_otsutstviya.py` (`/api/кадры/отсутствия`).
  `main.py` больше не трогать — свои ручки дописывать в свой файл.
- Таск 01 уже заменил имя таблицы в SQL внутри `services/kadry.py` и
  `services/kadry_analitika.py` (11 мест) — иначе оба падали. Это механическая
  правка, поверх неё и работайте.
- **Боевая база ещё не переехала**: переименование и перенос сработают при первом
  запуске `init_db`. Копия до работы — `~/.local/share/assistent-pb/backups/app.db.do-sostava`.
  Замер на копии: 6458 строк старых бригад → 769 периодов, все 2161 день всех 71
  месяца совпали до человека, `состав_на` — 0,6 мс.
- Бригады есть **только у ПожСервиса**; у ПожМастера их ноль. Экраны обязаны это
  переживать, а не показывать пустоту без объяснения.
